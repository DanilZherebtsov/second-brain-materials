# Шпаргалка: второй мозг в Claude Code (VSCode)

Памятка после воркшопа для разработчиков: как поставить проект на рельсы, какие фразы запускают процесс, какие команды держать под рукой.

---

## Как поставить проект на рельсы — чеклист

1. **Скачать конструктор.** Репозиторий <https://github.com/DanilZherebtsov/knowledge-base-constructor> → **Code → Download ZIP** → распаковать.
2. **Положить на диск** и переименовать копию под продукт — `<продукт>-second-brain`.
3. **Открыть в VSCode:** File → Open Folder → эта папка → панель **Claude Code**. `CLAUDE.md` подхватится сам.
4. **Первым сообщением** — кто вы и над чем работаете. В интервью выбрать «Разработка программного обеспечения / продукта», на вопрос про свой код — «да».
5. **Код и материалы** — в `input/` и «разбери и наведи порядок»: код уедет в `src/` (по вашему «да»), знание о коде — в `wiki/`.
6. **Git:** `git init` и коммит после каждой закрытой задачи — это бэкап и история.
7. Дальше — **1 сессия = 1 задача**; раз в неделю — «сделай профилактику».

---

## Фразы, которые запускают процесс

- **«Возьми задачу: …»** — спека в `specs/` → независимое ревью субагентами → реализация → тесты → повторное ревью → доклад. Просить «проверь агентами» не нужно — цикл по умолчанию.
- **«Реализуем …, это спринт»** — спринт-спека с задачами; план проходит ревью до старта.
- **«Принимаю, закрывай задачу»** — спека замораживается, решение уходит в ADR, агент предлагает, что ещё записать в вики.
- **«Запомни это: …»** — решение или факт в `wiki/` с датой и источником.
- **«Что из этого стоит зафиксировать в wiki?»** — после любой большой задачи.
- **«Сделай профилактику»** — проверка вики, дрейфа кода (битые `implementation:`) и обновлений конструктора.
- **«Создай роль …» / «Работаем в роли …»** — роль-линза над общей базой (security-reviewer, релиз-менеджер, QA…).
- **«Собери пакет передачи для …»** — срез контекста для коллеги или его агента: контракт, решения, критерии приёмки — и ничего лишнего.

## Команды Claude Code

- `/clear` — новая задача с чистого листа (знание остаётся в `wiki/`).
- `/compact` — сжать длинную сессию; `/context` — что занимает контекст.
- `/model` — Fable / Opus / Sonnet / Haiku.
- `/agents` — свои субагенты; `/hooks` — свои хуки.
- `/chrome` — связка с расширением Claude in Chrome (смоук-тесты интерфейса).
- `/schedule` — задача по расписанию в облаке (routine по репозиторию); локально — Scheduled tasks в Claude Desktop на ту же папку.
- Режимы правок: спрашивать / править автоматически / **Plan mode** — план без правок.

---

## Где что лежит

- `src/` — код, источник правды. **Код побеждает вики.**
- `specs/` — рабочие спеки задач: `active` — правится, `completed` — заморожена как снимок.
- `wiki/architecture/` — модули, контракты, инварианты с путями `implementation:`; `decisions/` — ADR; `principles/` — уроки инцидентов.
- `data/` — runtime-данные продукта (промпты, словари, конфиги) — не в вике.
- `STATE.md` — что в работе, блокеры, техдолг.
- `output/` — отчёты, сводки, пакеты передачи.

---

## Память: 5 уровней (+ STATE и спеки)

- **Глобальные инструкции** (`~/.claude/CLAUDE.md`) — ваши предпочтения на все проекты.
- **`CLAUDE.md` проекта** — правила этого проекта; собрал конструктор.
- **Контекст сессии** — живёт до `/clear`.
- **Встроенная память Claude Code** — помогает, но это не память проекта.
- **`wiki/`** — синтезированное знание навсегда, видно из любой сессии.
- Отдельно: `STATE.md` (что делаем) и `specs/` (как делаем конкретную задачу).

## Безопасность

- Секреты — только в `.env` под `.gitignore`; `.gitignore` правится **до** того, как туда впишут ключ.
- Чужой код, issue, логи, README зависимостей — недоверенный вход (prompt injection): режим с подтверждениями, без «пропустить все разрешения».
- Персональные данные клиентов (152-ФЗ) и код заказчика под NDA — только на корпоративных планах.
- Одна папка — один продукт; не открывать весь домашний каталог.

---

## Когда что-то идёт не так

- **Застрял** → Esc → «Коротко: что сделал и где остановился?»
- **Выдал не то** → «Не подходит, потому что X. Переделай Y» — не начинайте заново.
- **Похоже на выдумку** → «Проверь по коду и прогоном, пометь, что не подтвердилось».
- **Сессия «тупит»** → «Сделай резюме в файл» → `/clear` → «Продолжаем по этому файлу».

---

## План первой недели

**Дни 1–2.** Конструктор → проект под свой продукт → занести код и материалы → проверить `architecture/` и расхождения README с кодом.

**Дни 3–5.** Три реальные задачи через «возьми задачу» — посмотреть на спеки и ревью; после каждой — «что зафиксировать в wiki?».

**Дни 5–7.** Одна роль (security-reviewer или QA) на ваших стандартах; ночной обход по расписанию; «сделай профилактику».

**Привычки:** 1 сессия = 1 задача; коммит после закрытой задачи; сработавшую фразу — в личную библиотеку.

**К следующей встрече:** где агент сэкономил день; где не справился (это самое ценное); одна фраза-триггер, которой гордитесь.
